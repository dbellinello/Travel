🔗 Toolbar

Source of truth — Brain/Reference/Toolbar.html

Status: UNIVERSAL — every HTML page in the Travel workspace includes the toolbar.

Source file: Travel/toolbar.js — one file, one edit updates every page.

Summary: A shared navigation bar rendered at the top of every page. Links all Trip Essentials files and the Guides index so the reader can navigate without returning to a root page. The active page highlights automatically. The toolbar reads the page background color at runtime and adapts its accent — no per-page style override is needed.

Related file: Navigation.html — prev/next arrow rules for guide sequences.

§ 1. Required markup

Place the mount div and script tag immediately after the opening <body> tag, before any other content. Both are required on every new page.

<div id="toolbar-mount" data-depth="N" data-maxwidth="W"></div> <script src="PATH/toolbar.js"></script>

Omitting the mount div silently skips the toolbar. Omitting either attribute produces a mis-sized or broken navigation bar.

Optional attribute: data-toolbar-theme="guide" forces the guide accent color on pages that do not have the guide background color — used on the Guides index page, which has a non-guide background but should visually match the guide family. Omit this attribute on all other pages; the toolbar detects the accent automatically from the page background.

§ 2. data-depth

Set to the number of directory levels the page sits below Travel/. The toolbar uses this value to build relative hrefs to every other page and to locate toolbar.js.

  • 1 — page lives directly inside Trip Essentials/ (e.g. Trip Essentials/Travel Packing.html). Script path: ../toolbar.js
  • 2 — page lives one subfolder deeper (e.g. Trip Essentials/Plug Adapter/Plug Adapter Guide.html). Script path: ../../toolbar.js
  • 2 — guide pages inside Guides/{City}/ also use depth 2. Script path: ../../toolbar.js

The src attribute on the <script> tag must match the depth — one ../ per level.

§ 3. data-maxwidth

Set to match the page's own content width so the toolbar aligns with the body text.

  • 760 — Trip Essentials pages
  • 940 — Guide pages

§ 4. Adding a page to the menu

The menu is defined in the ITEMS array inside Travel/toolbar.js. To add a new page, add one entry to that array. One edit propagates to every page that loads the script — do not add link markup to individual HTML files.

Each entry takes two keys: href (path relative to Travel/, URL-encoded) and text (the label shown in the bar). Two additional entry forms are supported: a null entry inserts a visual separator between groups of links; an entry with guides: true marks the Guides link so the script can apply distinct styling to it. Do not add link markup to individual HTML files — one edit to the array propagates to every page.

§ 5. Footer sharing link (injected by toolbar.js — every page)

The footer sharing link is injected by toolbar.js, not written into each file. One definition lives in toolbar.js and applies to every page that loads it — Trip Essentials, the Guides index, and every guide. The link is cosmetic — it displays the page's public URL so the reader can copy or share it.

The injected link points to the page's own live URL, derived at runtime from location. Because it reads the real address, it is correct no matter what the GitHub repo is named or how folders are arranged, and it survives repo renames with no per-file edits. (The current published base is https://dbellinello.github.io/Travel/; only the SITE_BASE constant in toolbar.js — used solely for offline file:// previews — names the repo.)

Because the footer is injected, a shipped guide must not contain an inline footer <div> with a hardcoded public URL. A guide only needs to load toolbar.js (see §1–§4); the footer then appears automatically. A leftover inline footer would duplicate the injected one and pin a stale repo name. The same applies to Trip Essentials pages.
