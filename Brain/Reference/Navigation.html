🧭 Navigation

Reference — Brain/Reference/Navigation.html

Status: Reference. Describes the navigation aids the shared script renders at runtime, plus the search behaviour on pages that carry a search box.

Source file: Travel/toolbar.js — one file renders the toolbar, the side arrows, the scroll aids, and the shared footnote on every page that loads it.

Related files: Toolbar.html — toolbar mount markup, depth, maxwidth, and menu management. Guide-page footer links are governed by Toolbar.html § 5.

Summary: The shared footnote is the navigation element that carries across to the guides — every Trip Essentials page and the guides index renders one identical sharing link, generated from the page path. Prev/next arrows chain the guide sequence. The scroll bar and scroll button are passive aids. On a search page, a query with no matches collapses the page to its title, the search box, and the no-match message.

§ 1. Shared footnote (the link shared with the guides)

The shared footnote is a single centred sharing link rendered as the last element on the page. It displays the page's own public address so the reader can copy or share it. The script generates it automatically from the page path — there is nothing to write into each file and nothing to keep in sync. The link opens in a new tab; the display text matches the address with no scheme prefix.

The footnote renders on every page that loads toolbar.js — every Trip Essentials page, the guides index, and every guide. No page carries an inline footer of its own; toolbar.js injects the single shared link, so there is never a duplicate. On a page served over the web the link is the page's own live address; only an offline file:// preview falls back to the SITE_BASE constant. Full rule: Toolbar.html § 5.

§ 2. Prev / next arrows

Guide pages that belong to a sequence carry data-prev and data-next attributes on the toolbar mount div. When present, the script renders fixed left and right side arrows pointing to the neighbouring guide. Both are optional — a guide with no predecessor omits data-prev; a guide with no successor omits data-next.

<div id="toolbar-mount" data-depth="2" data-maxwidth="940" data-prev="../CityA/guide_vN.html" data-next="../CityC/guide_vN.html"></div>

Paths are relative to the guide file's own directory. Each value points to the neighbouring guide's HTML file — not to a folder or an index page. Trip Essentials pages do not use these attributes.

§ 3. Chain integrity

The guide sequence is a doubly-linked chain: every guide's data-next matches the following guide's data-prev, and vice versa. A mismatched path, a stale filename after a version bump, or a guide added without updating its neighbours leaves one or both arrows dead. When a guide is added or renamed, the two adjacent guides in the chain are updated in the same change.

§ 4. Canonical order and guides_index

The canonical guide order is defined in Guides/guides_index.html. Every guide card in the index carries matching data-guide-prev and data-guide-next attributes. When the chain changes, both the guide file's mount div and the index card are updated together.

Within each region section, guides are ordered alphabetically by city name — case-insensitive, diacritics normalized (Ålesund sorts as Alesund, Montréal as Montreal). The validator enforces this order and reports the first out-of-order city per region.

§ 5. Adding a new guide to the chain

Insert the new guide between its two neighbours. All four steps happen in a single pass — partial updates break the chain:

  1. Add the new guide's card to guides_index.html in the correct region section, placed in alphabetical order by city name within that region.
  2. Update the predecessor card's data-guide-next and the successor card's data-guide-prev to point to the new guide.
  3. Update the banner destination count and the region guide count in guides_index.html.
  4. Set the new guide file's own toolbar-mount data-prev and data-next to match its neighbours.

§ 6. Scroll progress bar

The script renders a thin progress bar fixed along the top of the viewport. Its width tracks how far the reader has scrolled through the page. It is passive — no markup or configuration per page.

§ 7. Scroll button

The script renders one persistent circular button at the right edge of the viewport. It points down while the reader is above the foot of the page and scrolls to the bottom on click; once near the bottom it flips to point up and scrolls back to the top. One button, both directions, on every page.

Search behaviour on the Trip Essentials pages — including how a no-match query collapses the page and hides the shared footnote — lives in Trip Essentials/Essentials Pages - Rules.md.
