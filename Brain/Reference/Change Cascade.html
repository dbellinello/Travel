🔀 Change Cascade Map

Brain/Reference/ · Last updated: 2026-05-26 — icon cascade expanded; icon retired/deleted cascade added

📌 Purpose

Read this file before touching any CORE RULES file, validator, section name, icon, guide CSS, or starting a new guide build. It lists every downstream file that must follow each type of change. Nothing should ship without checking its cascade first.

Direction is one-way. Changes trigger cascades; this map documents the cascades. The CORE RULES HTML files are the source of truth — this map never overrides them.

📄 CORE RULES file edited

Any change to a file in Brain/CORE RULES/ — wording, thresholds, format rules, section additions.

⚠️ Cascade — CORE RULES file edited
Affects: validator integrity check · downstream rule consumers · both Brain docs
  • Regenerate checksums — run Brain/scripts/update_core_rules_checksums.py to update Brain/scripts/core_rules_checksums.json
  • Check if Brain/scripts/validate_itinerary.py references the changed rule — if yes, update the validator logic and label to match
  • Update Brain/Reference/Validator Index.html if any validator check was added, changed, or removed
  • Update Brain/Reference/Rule Dependencies.html — update the relevant icon card, concept block, or threshold entry to reflect the new rule value
  • If the change affects a threshold or format used in multiple CORE RULES files, check Rule Dependencies.html for all files that share that rule — update them all before regenerating checksums
  • CORE RULES files are read-only and can only be changed by explicit request and permission. Do not edit without that gate.

🧪 Validator check added / changed

Any modification to Brain/scripts/validate_itinerary.py — new check, retired check, threshold change, bug fix.

⚠️ Cascade — validator check added or changed
Affects: coverage doc · dependency map · all guides (run to confirm)
  • Update Brain/Reference/Validator Index.html — add new check under the correct section; mark ✅ / ❌ / ⚠️; update section item count in the section heading
  • Update Brain/Reference/Rule Dependencies.html — if the check enforces a rule that is cross-referenced, update the relevant icon card or concept entry
  • Add a changelog entry at the top of the .meta block in Brain/Reference/Validator Index.html — one line, date + what changed
  • Run Brain/scripts/audit_all_guides.py (or validate each guide individually) to confirm no regressions across all guides
  • If the check enforces a new format rule not yet documented in CORE RULES, log it in 🔧 Rules for Update in To_Do_List.md before shipping

🏷 Section renamed

Any change to an extras section's canonical name, id, or display title — e.g. renaming "Tours" → "Guided Tours".

⚠️ Cascade — section renamed (highest impact change type)
Affects: every CORE RULES file, every guide, validator in ~8 places, and all Brain docs
  • Rename the CORE RULES HTML file in Brain/CORE RULES/ to match the new section name (requires explicit permission)
  • Update Brain/CORE RULES/Guide Structure.html — section name in the extras order list
  • Update Brain/CORE RULES/Icon Order and Format.html — section heading and any icon-position references that name the section
  • Update Brain/CORE RULES/Trip at a Glance.html — pill label in the extras row if it references the section name
  • Update all guides — for each: (1) section id= attribute, (2) any href="#..." anchors pointing to it, (3) .extras-title display text
  • Update Brain/scripts/validate_itinerary.py in all of: canonical id map · legacy id map · BUILD_STATE_PHASE_4_MAP · pill label check · any drift sentinel that references the old name
  • Update all _build/build_state.md files (every guide) — section name in the phase 4 tracker
  • Update Brain/Reference/Validator Index.html — section heading for that section's checks
  • Update Brain/Reference/Rule Dependencies.html — any icon card or concept entry that names the section
  • Regenerate checksums — run update_core_rules_checksums.py
  • Run validator on all guides after all changes are complete — confirm zero new failures before closing the task

🔣 Icon added / changed

Any change to an icon used in guide entries — new icon introduced, existing icon reassigned, char-limit changed, position changed.

⚠️ Cascade — icon added or changed
Affects: Icon Order doc · possibly Motion Rule · validator regex + allowlists · both Brain docs · all guides using the icon · checksums
  • Update Brain/CORE RULES/Icon Order and Format.html — add / update the icon's position, format, and char-limit entry (requires explicit permission)
  • If the icon is a motion icon (transport, direction, timing), update Brain/CORE RULES/Motion Rule.html accordingly (requires explicit permission)
  • Update any other CORE RULES files that reference this icon by name or position (Day Structure, Stops Structure, Guide Structure, Getting Around, etc.)
  • Update Brain/scripts/validate_itinerary.py — update: (1) allowlist regex for the affected row/section; (2) _SECTION_ICON_ALLOWLISTS dict if the icon is used as an .extras-sub heading prefix; (3) any row-shape check that references the icon; (4) drift sentinel to catch guides still using the old icon
  • Update all affected guides — search every guide for the old icon in the affected context and replace with the new icon; run the validator on each to confirm no regressions
  • Update Brain/Reference/Validator Index.html — update affected check items; add a changelog entry
  • Update Brain/Reference/Rule Dependencies.html — add a new icon card (for new icons) or update the existing card with new format/position details
  • Regenerate checksums — run update_core_rules_checksums.py
  • If the icon appeared in .extras-sub headings across multiple sections, verify each section's allowlist entry is updated — _SECTION_ICON_ALLOWLISTS is a separate dict from the general row-shape regexes
  • After all guide updates, run Brain/scripts/audit_all_guides.py across all guides to confirm zero new failures

🗑 Icon retired / concept deleted

An icon or structural concept is removed entirely — no replacement, class deleted, banner concept dropped.

⚠️ Cascade — icon retired or concept deleted
Affects: all guides using the old icon · validator · CSS if a class is involved · both Brain docs · CORE RULES · checksums
  • Update the relevant CORE RULES file(s) to remove the concept — remove icon from Icon Order and Format.html, Motion Rule.html, or any file that names it (requires explicit permission)
  • Remove the old icon / class from all affected guides — convert any divs or rows that used it to the correct replacement format; do not delete content, only change form
  • Update Brain/scripts/validate_itinerary.py — (1) remove the old icon from all allowlists and regexes; (2) add a hard-fail drift sentinel so any guide still using the old element fails immediately; (3) remove any check that was validating the now-deleted concept
  • If a CSS class was deleted, remove it from guide_v2.css (both copies — Guides/guide_v2.css and Brain/Reference/Guide Style.css) and add a drift sentinel for the old class name
  • Update Brain/Reference/Validator Index.html — mark old check items as retired; add new stale-sentinel item; add changelog entry
  • Update Brain/Reference/Rule Dependencies.html — mark the icon card or concept entry as retired
  • Regenerate checksums — run update_core_rules_checksums.py
  • Run validator on all guides after completion — the drift sentinel should produce zero failures if every guide was correctly updated

🗺 New guide built

A completed guide is ready to ship — all phases done, validator passing.

✅ Cascade — new guide built
Affects: guides index · build state · validator run
  • Update Guides/guides_index.html — four steps, one edit: (1) add new card in the correct region section with the right data-guide-num; (2) update predecessor's data-guide-next and successor's data-guide-prev; (3) update banner destination count and region guide count; (4) set the guide file's own toolbar-mount data-prev/data-next to match neighbours. Full spec: Brain/Reference/Navigation.html § 5 · Brain/Reference/Ship Checklist.html § 11
  • Create Guides/[City]/_build/build_state.md — populate all phase entries
  • Run Brain/scripts/validate_itinerary.py on the new guide — must pass (zero hard-fails) before shipping
  • If the Tours section is built, remove the guide from TOURS_EXCLUDED_GUIDES in the validator to switch on per-source minimum enforcement

🎨 CSS rule changed

Any change to Guides/guide_v2.css — new rule, retired rule, value change.

⚡ Cascade — CSS rule changed
Affects: all guides (visual) · validator drift sentinels if a class is retired
  • Update Brain/Reference/Guide Style.css (source of truth) and copy to Guides/guide_v2.css (GitHub Pages deploy copy) — keep both in sync
  • If the change retires an old class or id, add a drift sentinel to Brain/scripts/validate_itinerary.py that hard-fails any guide still using the old class — update Brain/Reference/Validator Index.html to log the new sentinel
  • Run Brain/scripts/audit_all_guides.py across all guides to confirm no visual regressions and no new drift-sentinel failures
  • Inline style= attributes with layout properties in any guide are a validator hard-fail — do not use inline styles to work around a CSS change

✏️ Existing guide content edited

A change to guide content — entry swap, text edit, new stop added, section rebuilt.

✅ Cascade — guide content edited
Affects: the guide only
  • Archive the guide before editing — copy to Travel/archive/[guide]_pre-[reason]_[date].html
  • Run Brain/scripts/validate_itinerary.py on the edited guide after saving — confirm zero new hard-fails
  • If a skip-listed venue was involved, confirm against Brain/CORE RULES/ Cities Skip List before adding or removing
  • If the edit resolves a known to-do item, delete the item from To_Do_List.md — no strikethrough
Reminder: This file is part of Brain/Reference/ — update it whenever a new change type is identified or an existing cascade is found to be incomplete.
